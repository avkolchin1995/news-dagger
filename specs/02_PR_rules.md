# Правила ведения проекта

## Методология разработки

Разработка ведется по гибкой методологии. Процесс делится на спринты. Также существует понятие MVP, благодаря которому определенную часть работы вывести в релиз.

```
[Бэклог] --> [В работе] --> [Ревью] --> [Готово] --> [Архив]
```

## Конвейер разработки

```
[Цель] --> [User Story] --> [Use Case] --> [Задача] --> [Ветка] --> [Коммит] --> [PR] --> [Стенд] --> [Релиз]
```

## Задачи

### Категории

| **Категория** | **Описание** |
| :--: | :--: |
| `DOCS` | Документация, исследования, анализ |
| `INFRA` | Инфраструктура |
| `DE` | Инженерия данных |
| `QA` | Тестирование |

### карточка

```
**CAT-XXX**: *Что нужно сделать в начальной форме глагола*

*Описание задачи*

*Критерии приемки*
```

## Ветки

### Категории

| **Категория** | **Описание** |
| :--: | :-- |
| `master` | Релизная ветка. В нее можно делать PR только из `dev`. |
| `dev` | Ветка разработки. В нее нужно делать PR из других веток. |
| `feat` | Функциональность |
| `hotfix` | Исправление бага |
| `refactor` | Рефакториг |

### Название

`Категория ветки` + `/` + `Задача`

## Коммиты

```
Идентификатор задачи: Что сделано в прошедшем времени

Подробное описание сделанного
```

## PR (Pull Requests)

```
[коммит] -> [code review] -> [PR] -> [dev]
```
